# Git 提交规范

## 格式
每次提交信息必须遵循以下结构，版本号第一行，空行第二行，变更列表从第三行开始：
v1.0.1
1. 修复了 xxx
2. 更新了 xxx

- 第一行仅写版本号（如 v1.0.1）。
- 第二行起为有序列表，每条描述具体变更，不加类型前缀。

## 版本号递增规则
版本号格式：vX.Y.Z（主版本.次版本.修订号）。
- 原型机/开发阶段：从 v0.0.0 开始，按需递增。
- 首次正式发布：v1.0.0。
- 架构大变革/破坏性变更：主版本号 +1（v2.0.0）。
- 模块级新增或重构：次版本号 +1（v1.1.0）。
- 修复小缺陷/细微优化：修订号 +1（v1.0.1）。

## 示例
v1.0.1
1. 修复用户登录超时未重定向
2. 统一首页按钮圆角样式
3. 升级 axios 到 1.7.2

v2.0.0
1. 重构权限系统，引入 RBAC 模型（破坏性变更）
2. 新增组织管理模块
